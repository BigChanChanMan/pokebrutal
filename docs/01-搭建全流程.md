## 第 0 步 · 环境预检

动手前先确认工具链和网络。别跳过这步 —— 后面的问题十有八九能在这里提前发现。

```bash
node -v && pnpm -v && git --version

# 确认关键外部服务可达
curl -o /dev/null -w "%{http_code}\n" https://pokeapi.co/api/v2/pokemon/1
curl -o /dev/null -w "%{http_code}\n" https://neobrutalism.com/r/base/button.json
curl -o /dev/null -w "%{http_code}\n" https://www.shadcn.com.cn/
```

三个都返回 `200` 才算通。任何一个是 `000`，先解决网络再继续。

## 第 1 步 · 创建 TanStack Start 脚手架

**为什么用 CLI 而不是手搭**：TanStack Start 涉及 Vite 插件、SSR 入口、路由生成器、Nitro 构建四块配置，
手搭容易漏。官方 CLI 一条命令全部配好。

先看一眼 CLI 有哪些参数（这一步能省掉后面很多试错）：

```bash
npx @tanstack/cli@latest create --help
```

然后创建项目：

```bash
npx @tanstack/cli@latest create pokebrutal \
  --framework React \
  --package-manager pnpm \
  --no-examples \
  --no-git \
  --no-intent \
  --deployment nitro \
  --non-interactive --yes

cd pokebrutal && pnpm install
```

**关键参数解释**：

| 参数 | 作用 |
|---|---|
| `--framework React` | 选 React（另一个选项是 Solid） |
| `--package-manager pnpm` | 锁定包管理器，避免 CI 里猜错 |
| `--no-examples` | 不要 demo 页面，从干净状态开始 —— 学习项目建议这样 |
| `--deployment nitro` | 用 Nitro 做构建产物，产出标准的 Node server，不绑平台 |
| `--non-interactive --yes` | 全程不交互，可脚本化复现 |

**产出的关键文件**：

```
pokebrutal/
├── package.json          # dev/build/preview 脚本 + 依赖
├── vite.config.ts        # devtools + nitro + tailwindcss + tanstackStart + viteReact
├── tsconfig.json         # ★ 已内置 "@/*": ["./src/*"] 别名
├── src/
│   ├── router.tsx        # 路由器实例 + Register 类型声明
│   ├── routes/__root.tsx # 根路由（<html> 骨架）
│   ├── routes/index.tsx  # 首页占位
│   └── styles.css        # 样式入口（含 @import "tailwindcss"）
```

> **重点**：`tsconfig.json` 里默认就有 `"@/*": ["./src/*"]`。这正是 shadcn 需要的别名 ——
> 用 Next.js 或裸 Vite 时很多人卡在这一步，TanStack 模板帮你省了。

## 第 2 步 · 补上 cn() 工具函数

**为什么必须先做**：neobrutalism / shadcn 的**每一个**组件源码里都有：

```tsx
import { cn } from "@/lib/utils"
```

没有这个文件，组件装进来会直接编译报错。

```bash
pnpm add clsx tailwind-merge
```

新建 `src/lib/utils.ts`：

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

**两个包各管什么**：

- `clsx` —— 条件拼接。`clsx('a', cond && 'b')` → `"a b"`
- `tailwind-merge` —— 消解 Tailwind 类冲突。`twMerge('p-2 p-4')` → `"p-4"`

缺了 `tailwind-merge`，你通过 `className` 覆盖组件默认样式时会出现「两个类都在、谁生效看 CSS 顺序」的随机问题。

## 第 3 步 · 写 components.json

**这是什么**：shadcn CLI 的「项目说明书」。它告诉 CLI：别名在哪、CSS 文件在哪、能装哪些第三方 registry。

正常路径是跑 `npx shadcn@latest init`，但它是交互式的（会依次问 TypeScript、style、base color…）。
无 TTY 的环境下会卡住，所以我们手写一份 —— 顺便把每个字段讲清楚。

新建 `components.json`：

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/styles.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "iconLibrary": "lucide",
  "registries": {
    "@neobrutalism": "https://neobrutalism.com/r/radix/{name}.json",
    "@neobrutalism-base": "https://neobrutalism.com/r/base/{name}.json"
  }
}
```

**逐字段说明**：

| 字段 | 值 | 为什么 |
|---|---|---|
| `style` | `"new-york"` | 组件风格取向。`default` 已弃用 |
| `rsc` | `false` | TanStack Start **不是** React Server Components 项目。填 `true` 会让 CLI 给组件加无用的 `"use client"` |
| `tsx` | `true` | 生成 `.tsx` 而非 `.jsx` |
| `tailwind.config` | `""` | **Tailwind v4 不需要配置文件**，必须留空 |
| `tailwind.css` | `"src/styles.css"` | 全局 CSS 入口。组件需要的 CSS 变量会被合并写到这里 |
| `tailwind.cssVariables` | `true` | 用 CSS 变量做主题。neobrutalism **必须**是 true |
| `aliases.utils` | `"@/lib/utils"` | `cn()` 的导入路径，必须和上一步创建的文件对得上 |
| `aliases.ui` | `"@/components/ui"` | 决定组件被写到哪个目录 |
| `iconLibrary` | `"lucide"` | neobrutalism 组件依赖 `lucide-react` |
| `registries` | 见第 4 步 | 第三方 registry 命名空间 |

## 第 4 步 · 注册 neobrutalism 命名空间

**核心认知**：`neobrutalism.com` **不是一个 npm 包**。它是一个符合 shadcn registry 协议的
HTTP JSON 端点。所以不能用 `pnpm add neobrutalism` 装它。

验证它确实是 registry：

```bash
# 这是个目录索引，列出全部 54 个 item
curl -s https://neobrutalism.com/r/registry.json | head -c 400

# 这是单个组件（含完整源码）
curl -s https://neobrutalism.com/r/base/button.json | head -c 400
```

URL 规律：

```
https://neobrutalism.com/r/{base|radix}/{component}.json
```

- `base` → 底层用 `@base-ui/react`
- `radix` → 底层用 `radix-ui`

上一步 `components.json` 的 `registries` 字段已经把两个都登记好了：

```json
{
  "registries": {
    "@neobrutalism": "https://neobrutalism.com/r/radix/{name}.json",
    "@neobrutalism-base": "https://neobrutalism.com/r/base/{name}.json"
  }
}
```

登记后就能用简写安装：

```bash
npx shadcn@latest add @neobrutalism-base/button
```

等价于：

```bash
npx shadcn@latest add https://neobrutalism.com/r/base/button.json
```

**验证命名空间生效**（重要，先 dry-run 再真跑）：

```bash
npx shadcn@latest add @neobrutalism-base/button --dry-run
```

预期输出：

```
┌ shadcn add @neobrutalism-base/button (dry run)
│
├ Files (1) +1 new
│ + src/components/ui/button.tsx  create
│
├ Dependencies (2)
│ + @base-ui/react
│ + class-variance-authority
```

看到这个说明 registry 解析成功。

## 第 7 步 · 准备宝可梦数据

**为什么不用运行时请求**：列表页要做本地搜索 + 排序，静态数据才能做到零延迟。
详情页再走 loader 实时抓 —— 两种策略各有各的场景。

### 7.1 抓中文名

PokeAPI 的中文名**不在** `/pokemon/{id}` 里，要走 `/pokemon-species/{id}` 的 `names` 数组，
筛 `language.name === 'zh-hans'`。

`scripts/fetch-zh-names.mjs`：

```js
const IDS = Array.from({ length: 151 }, (_, i) => i + 1)
  .concat([152, 155, 158, 252, 255, 258, 387, 390, 393, 448, 445, 133, 143, 196, 197, 700, 778, 887, 1007])

const out = {}
let cursor = 0
async function worker() {
  while (cursor < IDS.length) {
    const id = IDS[cursor++]
    const r = await fetch(`https://pokeapi.co/api/v2/pokemon-species/${id}`)
    if (!r.ok) continue
    const j = await r.json()
    out[id] = {
      zh: j.names.find((n) => n.language.name === 'zh-hans')?.name ?? null,
      en: j.names.find((n) => n.language.name === 'en')?.name ?? j.name,
      ja: j.names.find((n) => n.language.name === 'ja')?.name ?? null,
    }
  }
}
await Promise.all(Array.from({ length: 12 }, worker))  // 12 并发
console.log(JSON.stringify(out))
```

跑它并生成 TS 模块：

```bash
node scripts/fetch-zh-names.mjs > /tmp/zh.json
# 再把 JSON 转成 src/data/zh-names.ts
```

覆盖范围：**第一世代全 151 只 + 历代御三家、人气异兽、传说宝可梦，共 168 只。**

### 7.2 抓图鉴快照

## 第 8 步 · 写属性克制表

`src/lib/type-chart.ts`。这是全站唯一的「业务逻辑」。

**核心是一个 18×18 的静态常量表**：

```ts
export const TYPE_CHART: Record<PokemonType, {
  super: PokemonType[]    // 2 倍
  notVery: PokemonType[]  // 0.5 倍
  immune: PokemonType[]   // 0 倍
}> = {
  fire: {
    super: ['grass', 'ice', 'bug', 'steel'],
    notVery: ['fire', 'water', 'rock', 'dragon'],
    immune: [],
  },
  // …另外 17 个
}
```

**双属性倍率相乘** —— 这是宝可梦的官方规则，也是「四倍弱点」的由来：

```ts
export function effectivenessAgainst(attack: PokemonType, defenders: PokemonType[]): number {
  const rel = TYPE_CHART[attack]
  return defenders.reduce((multiplier, def) => {
    if (rel.immune.includes(def)) return multiplier * 0
    if (rel.super.includes(def)) return multiplier * 2
    if (rel.notVery.includes(def)) return multiplier * 0.5
    return multiplier
  }, 1)
}
```

`火 + 飞行` 打 `岩石`：岩石克火(×2) × 岩石克飞行(×2) = **4 倍**。

再包一层 `matchupTable()` 输出全部 18 个属性的倍率，供计算器页面用。

## 第 9 步 · 封装 PokeAPI 访问层

`src/lib/pokeapi.ts`。

**关键约束**：这个文件既会在**服务端**执行（SSR loader），也会在**客户端**执行
（前端导航时）。所以只能用全局 `fetch`，**不能碰 `window`、`document`、`localStorage`**。

```ts
const API = 'https://pokeapi.co/api/v2'

export function fetchPokemon(idOrName: string | number, signal?: AbortSignal) {
  return getJson<ApiPokemon>(`${API}/pokemon/${idOrName}`, signal)
}
export function fetchSpecies(idOrName: string | number, signal?: AbortSignal) {
  return getJson<ApiSpecies>(`${API}/pokemon-species/${idOrName}`, signal)
}
export function fetchEvolutionChain(url: string, signal?: AbortSignal) {
  return getJson<{ chain: EvolutionNode }>(url, signal)
}
```

还要处理进化链 —— PokeAPI 返回的是嵌套树，需要拍平：

```ts
export function flattenEvolution(node: EvolutionNode, stage = 0, acc = []) {
  acc.push({ stage, id: idFromUrl(node.species.url), name: node.species.name,
             detail: describeEvolution(node.evolution_details[0]) })
  for (const child of node.evolves_to) flattenEvolution(child, stage + 1, acc)
  return acc
}
```

> **健壮性**：进化链是「锦上添花」的数据，抓失败不该让整页 500。loader 里必须 try/catch 降级。

### 10.2 详情页的 SSR loader（本项目技术含量最高的一处）

```tsx
export const Route = createFileRoute('/dex/$id')({
  loader: async ({ params }) => {
    // ★ 这个函数在服务端跑 → SSR；客户端导航时在浏览器再跑一次
    const [pokemon, species] = await Promise.all([
      fetchPokemon(params.id),
      fetchSpecies(params.id),
    ])

    let evolution = []
    if (species.evolution_chain?.url) {
      try {
        const chain = await fetchEvolutionChain(species.evolution_chain.url)
        evolution = flattenEvolution(chain.chain)
      } catch {
        evolution = []   // 降级：进化链失败不影响整页
      }
    }

    return { pokemon, species, evolution }
  },
  head: ({ loaderData }) => ({
    meta: [{ title: `${loaderData?.pokemon.name} — POKÉBRUTAL 图鉴` }],
  }),
  component: PokemonDetail,
})

function PokemonDetail() {
  const { pokemon, species, evolution } = Route.useLoaderData()  // ★ 类型全自动推导
  // …
}
```

### 10.3 复用 Badge 做属性徽章

这是「registry 组件可定制」的最小示例 `src/components/type-badge.tsx`：

```tsx
export function TypeBadge({ type }: { type: PokemonType }) {
  return (
    <Badge
      variant="outline"
      className="h-6 border-2 border-black px-2 font-head"
      style={{ backgroundColor: TYPE_VARS[type] }}   // ← 注入属性色
    >
      {TYPE_LABELS[type]}

```

因为组件源码在你项目里，你可以随便传 `className` / `style` 覆盖 —— 这就是 registry
「拷贝源码」模式相比 npm 依赖包的最大好处。

## 想继续改造？几个入手点

1. **换配色**：改 `src/styles.css` 的 `:root` 里 `--primary` / `--background` / `--accent` 三个值
2. **换质感**：把 `--radius` 改成 `0.5rem`，立刻从粗野风变圆润风
3. **换阴影**：把 `--shadow-md` 从 `4px 4px 0 0` 改成 `4px 4px 8px 0`（加模糊半径）就变成常规投影
4. **加页面**：新建 `src/routes/team.tsx`，用 Card / Table / Dialog 做一个队伍编辑器
5. **加组件**：`npx shadcn@latest add @neobrutalism-base/calendar` —— registry 里还有 33 个组件没装
6. **做自己的 registry**：把 `src/components/type-badge.tsx` 抽出来，写 `registry.json`，
   `npx shadcn@latest build`，部署 `public/r/` —— 你就有了自己的组件分发源
