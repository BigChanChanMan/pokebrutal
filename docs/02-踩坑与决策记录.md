> 这份文档记录搭建过程中**真实遇到的问题**和处理方式。都是实测复现过的，不是"可能会遇到的"。

## 踩坑 1 · 批量安装时 `button` 被覆盖成 Radix 变体 🔴 最重要

### 现象

执行第 6 步的批量安装后，`npx tsc --noEmit` 报出一堆错误：

```
src/components/ui/button.tsx(3,21): error TS2307: Cannot find module 'cn' or its corresponding type declarations.
```

打开 `src/components/ui/button.tsx` 一看：

```tsx
import { Slot } from "radix-ui"        // ← 这是 Radix 变体！
import { cn } from "cn"                // ← 这个路径也是错的！
```

但命令里明明装的是 `@neobrutalism-base/button`（base = Base UI 变体）。

### 根因

两条线索交叉得出：

**线索一**：`dialog` 的 registry item 里有一行 `registryDependencies`：

```json
{
  "name": "dialog",
  "dependencies": ["@base-ui/react", "lucide-react"],
  "registryDependencies": ["button"]
}
```

注意 `"button"` 是**没有命名空间的裸名**。CLI 解析这个依赖时，走的是**默认 registry（shadcn 官方）**
而不是我们的 `@neobrutalism-base` 命名空间。

**线索二**：`.cta.json` 里项目预设是 `default`，`components.json` 的 `style` 是 `new-york`。
于是 CLI 从 shadcn 官方 registry 拉了一份 `new-york` 风格的 button —— 而这份源码的第一行 import
写的是 `import { cn } from "cn"`。

**结论**：批量安装时，后面的 `dialog` 触发了对 `button` 的递归解析，把先前装好的 Base UI 版
`button.tsx` **覆盖**成了 shadcn 官方版。

### 副作用：装进来两个垃圾依赖

因为那份错误源码里写了 `from "cn"` 和 `from "radix-ui"`，CLI 老实地往 `package.json` 里装了：

```json
"dependencies": {
  "cn": "^0.3.0",          // ← npm 上真有这个包，但跟 shadcn 的 cn() 毫无关系
  "radix-ui": "^1.6.7"     // ← 我们走 Base UI 路线，根本用不到
}
```

### 排查过程

```bash
# 1. 看哪些组件 import 了错误的 cn
grep -rn 'from "cn"' src/components/ui/

# 2. 对比 base / radix 两个 registry 返回的源码
curl -s https://neobrutalism.com/r/base/button.json  | grep -o 'import.*' | head -3
curl -s https://neobrutalism.com/r/radix/button.json | grep -o 'import.*' | head -3
# base  版第一行: import { Button as ButtonPrimitive } from "@base-ui/react/button"
# radix 版第一行: import * as React from "react" / import { Slot } from "radix-ui"

# 3. 看 dialog 的依赖声明，确认是 registryDependencies 引起的
curl -s https://neobrutalism.com/r/base/dialog.json | node -e "…"
```

### 解决

```bash
# 1. 重新装一次 button，单独跑就不会被后续依赖覆盖
npx shadcn@latest add @neobrutalism-base/button --overwrite --yes

# 2. 验证修好了
sed -n '1,5p' src/components/ui/button.tsx
# import { Button as ButtonPrimitive } from "@base-ui/react/button"   ✓

# 3. 清掉被误装的无关依赖（先确认没人用）
grep -rn "radix-ui\|from \"cn\"" src/
pnpm remove cn radix-ui
```

### 经验

> **批量 `shadcn add` 混用多个 registry 时，装完一定要检查被 `registryDependencies` 引用的组件。**
>
> 通用做法：
> 1. 批量装完 → 2. `npx tsc --noEmit` → 3. 对报错的文件单独 `add --overwrite` 修回
>
> 更稳的做法是**分批装**：先装被依赖的基础组件（button），再装依赖它们的（dialog）。

## 踩坑 2 · `shadcn init` 在无 TTY 环境卡死

### 现象

```bash
npx shadcn@latest init --template start --base radix -p nova --css-variables -y
```

即使带了 `-y --yes`，仍然停在：

```
? Would you like to use TypeScript (recommended)? › no / yes
```

`--yes` 只跳过**最终确认**，交互式的问卷仍然会问。试过的无效方案：

| 尝试 | 结果 |
|---|---|
| `-y` / `--yes` | 仍卡在 TypeScript 提问 |
| `< /dev/null` | 直接退出，不生成文件 |
| `CI=true` | 无效 |
| `printf '\n\n\n\n' \| ...` | 管道非 TTY，prompts 库不认 |
| `script -qec "..." /dev/null` | PTY 有了，但换行被当成回车提交了默认项，随后继续卡下一问（且输出被 ANSI 转义码淹没） |

环境里也没有 `expect`（只有 `script`）。

### 解决

**手写 `components.json`**。

这不是妥协 —— 反而更好。因为 `init` 做的事其实就是：
1. 生成 `components.json`
2. 往 CSS 里写主题变量
3. 装 `clsx` / `tailwind-merge` / `class-variance-authority` / `lucide-react`

这三件事我们本来就要手动做（见搭建流程第 2、3、5 步），自己写反而能把每个字段搞清楚。

### 经验

> **在有 TTY 的本地环境**，`npx shadcn@latest init --template start --base radix --css-variables`
> 是正确路径，跟着走就行。
>
> **在 CI / 容器 / 沙盒环境**，直接手写 `components.json`，别跟 prompts 库较劲。

## 踩坑 3 · 详情页漏了 Base UI 按钮的链接用法

### 现象

```tsx
<Button size="lg" render={<Link to="/dex" />}>进入图鉴</Button>
```

报错：

```
error TS2322: Property 'render' does not exist on type 'IntrinsicAttributes & ... ButtonHTMLAttributes<HTMLButtonElement>'
```

### 根因

我一开始读到的 `button.tsx` 是**被污染的 Radix 版本**（见踩坑 1），它用的是 `asChild`：

```tsx
// Radix 版签名
function Button({ asChild = false, ... }: React.ComponentProps<"button"> & { asChild?: boolean })
const Comp = asChild ? Slot.Root : "button"
```

修好之后拿到的是 **Base UI 版本**，它用的却是 `render` prop：

```tsx
// Base UI 版签名
function Button({ ... }: ButtonPrimitive.Props & VariantProps<typeof buttonVariants>)
```

而 `ButtonPrimitive.Props` 里确实有 `render` —— 但**只有 `render`、没有 `nativeButton`**（我一开始
猜了个 `nativeButton={false}`，也是错的）。类型检查把这个猜测挡下来了。

### 解决

底层的 `<ButtonPrimitive>` 只接受 `render`，不接受 `nativeButton`。但把 `<Link>`（渲染成 `<a>`）
塞进 button 语义里，本身就有可访问性隐患 —— Base UI 官方文档也明确说：
**做链接时不要用 `<Button render={<a />} nativeButton={false} />`，因为会给 `<a>` 加上 `role="button"`。**

所以最终改成直接用 `<Link>` + 手写按钮样式：

```tsx
<Link
  to="/dex"
  className="inline-flex h-11 items-center gap-2 border-2 border-border bg-primary px-6 font-head shadow-md transition-transform hover:-translate-x-0.5 hover:-translate-y-0.5"
>
  进入图鉴 <ArrowRightIcon className="size-4" />
</Link>
```

唯一的例外是「全部 168 只」那个幽灵按钮 —— 它确实需要 Button 的 variant 逻辑，
于是用 `render` 传 Link。**这个用法能编译通过但不推荐**，仅作演示。

### 经验

> **两种无头库的 API 差异要记牢**：
>
> | | 组合子 | 说明 |
> |---|---|---|
> | Radix UI | `asChild` | 布尔值，把样式让给孩子 |
> | Base UI | `render` | 传一个 React 元素 |
>
> 混用 registry 时，先看装进来的源码用的是哪套，再决定怎么写调用代码。

## 踩坑 4 · `species.cries` 不存在？

### 现象

```tsx
{species.cries?.latest ? <audio src={species.cries.latest} /> : null}
```

```
error TS2339: Property 'cries' does not exist on type 'ApiSpecies'
```

### 根因

不是数据的问题 —— `cries` 字段**确实存在**，是我手写的 `ApiSpecies` interface 漏了这个字段。

关于它到底在哪个接口上，实测确认：

```bash
curl -s https://pokeapi.co/api/v2/pokemon/6 | node -pe "Object.keys(JSON.parse(require('fs').readFileSync(0)).cries||{})"
# latest,legacy          ← pokemon 上也有

curl -s https://pokeapi.co/api/v2/pokemon-species/6 | node -pe "!!JSON.parse(require('fs').readFileSync(0)).cries"
# true                   ← species 上也有
```

两个端点的响应都没打包进类型里。手写类型定义时容易漏 —— 这是手写 API 类型的固有风险。

### 解决

补进 interface：

```ts
export interface ApiSpecies {
  // …
  /** 叫声音频。注意它在 species 上，不在 pokemon 上 */
  cries?: { latest?: string | null; legacy?: string | null }
}
```

### 经验

> **手写第三方 API 类型时，别凭印象写**。先 `curl` 一份真实响应，把字段抄全。
> 或者用 `openapi-typescript` 之类的工具从 schema 生成。
>
> 更省事的做法：给不确定的字段加 `?` 和 `| null`，再用运行时兜底。

## 踩坑 5 · Tailwind v4 让按钮失去了手型光标

### 现象

所有 `<button>` 悬停时是箭头光标，不是手型。对粗野主义这种强调「可点」的风格是致命的。

### 根因

Tailwind CSS v4 的 preflight 把按钮的 `cursor` 从 `pointer` 改成了 `default`，
理由是「按钮不一定是链接」。但对 UI 组件库来说，这个默认值反直觉。

### 解决

neobrutalism 官方也给了这个补丁（`--pointer` 是 `shadcn init` 的一个 flag）：

```css
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```

写进 `src/styles.css` 的 `@layer base` 里。

### 经验

> Tailwind 大版本升级时，**preflight（基础样式重置）的变化最容易被忽略**。
> 升级后第一件事就是翻 changelog 的 "Breaking Changes → Preflight" 一节。

## 踩坑 6 · 列表页 532KB 的 HTML

### 现象

```bash
curl -s -o /dev/null -w "%{size_download}\n" http://localhost:3000/dex
# 532528
```

图鉴列表页 SSR 出来 **520 KB** HTML。

### 分析

不是 bug，是权衡：

- 168 只宝可梦 × (立绘 img + 编号 + 中英名 + 属性徽章 + 种族值) ≈ 168 × 3KB
- SSR 把全部 168 个卡片一次性渲染进 HTML，所以首屏**零 JS 就能看到完整列表**
- 代价是 HTML 体积大

对比详情页 `/dex/25`：395 KB —— 因为它在 `<script>` 里内联了整个 loader 的返回数据
（`pokemon` + `species` + 进化链完整 JSON），用于客户端 hydration。

### 决策

**保持现状**。理由：

1. 168 条是刻意选的规模（第一世代全量 + 精选），不是失控的数据量
2. 首屏无 JS 可见 = 更好的 LCP 和可访问性
3. gzip 之后实际传输量约 40–60KB，可以接受

### 如果真要优化

几个方向，按性价比排序：

```tsx
// 1. 图片懒加载（已经做了）
<img loading="lazy" />

// 2. 分页或虚拟滚动
//    改成分页 24/页，HTML 体积直接除以 7

// 3. 只 SSR 首屏，其余交给客户端
//    用 useMemo 做本地分页，首屏渲染 24 个，滚动时增量渲染

// 4. 详情页只传必要字段给客户端，别内联整个 loader 数据
```

### 经验

> **SSR 不是「越全越好」**。列表页 SSR 全量适合「首屏即全部」的场景（搜索/筛选在本地做），
> 但如果列表会无限增长，就该引入分页或虚拟滚动。
>
> 判断标准：**这个页面的数据量会不会随业务增长？** 会 → 分页。

## 附：一次性数据脚本的处理

`scripts/fetch-zh-names.mjs` 把结果 `console.log` 到 stdout。第一次我直接重定向：

```bash
node scripts/fetch-zh-names.mjs > /tmp/zh.json
```

结果 JSON.parse 失败：

```
SyntaxError: Unexpected token 'c', "count: 168"... is not valid JSON
```

因为脚本里还有 `console.log('count:', ...)` 和 `console.log('missing zh:', ...)` 两行日志，
混进了 stdout。

**处理**：取最后一行（纯 JSON 那行）：

```bash
tail -n 1 /tmp/seed/zh-names.json > /tmp/seed/zh-names.clean.json
```

或者更规范的做法：日志一律走 `console.error`（stderr），数据走 `console.log`（stdout）。
本项目的 `fetch-dex.mjs` 就修正成了直接写文件，不再依赖 stdout 重定向。
